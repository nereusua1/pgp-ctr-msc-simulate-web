# 报文模拟系统产品与交互优化方案

本文描述目标设计与实施要求，不代表功能已经实现。新增建议应在对应阶段验证；涉及后端能力的项目须完成接口协作后交付。

## 阅读方式与决策状态

- **已确认**：此前逐项确认的角色、导航、独立页面、显式保存、发布隔离、整任务历史补跑及非目标，作为设计基线。
- **细化建议**：本轮为消除歧义补充的校验矩阵、执行快照范围、去重条件、默认值和页面规格，作为推荐实现方案；不代表后端已有相应能力。
- **待契约核对**：业务时区配置、数据源历史读取能力、连接检测结果、阶段事件及请求标识保留期限。接口核对完成前，不对这些能力宣告交付。

下文“业务规则细化”及页面规格中的默认值属于细化建议。实施清单中的编号用于关联开发任务和验收场景；文档未标记的功能均不得视为已实现。

## 目标与角色

将现有技术控制台优化为消息云联调管理工具：执行前可判断配置是否就绪，执行时可确认业务时间和投递范围，执行后可解释结果与失败原因。

- 管理员是核心用户，负责配置、发布、调度、执行和排障。
- 任务操作员只能查看运行信息、任务和执行记录，并对已有任务发起历史补跑。
- 投递目标只支持消息云组件。

界面统一使用“报文模板、消息云组件、执行批次、执行记录、历史补跑”等产品术语。完整定义参见根目录 CONTEXT.md。

权限必须同时由界面和后端约束：

- 管理员可以立即执行和历史补跑。
- 任务操作员只显示历史补跑，不能使用当前时间执行。
- 后端按角色校验执行模式，不能只依赖前端隐藏按钮。
- 权限不足时说明当前角色允许的动作，不使用笼统的“无权限”。

## 信息架构

管理员导航分为：工作台（运行总览）、配置管理（报文模板、数据项、消息云组件）、运行管理（任务管理、执行记录）。任务操作员只显示运行总览、任务和执行记录。

使用标准页面路由和面包屑，不采用全局多标签页。返回列表时恢复搜索、筛选、页码和滚动位置。

页面应具有稳定、可复制的 URL，至少覆盖运行总览、任务列表、任务详情、执行记录、执行批次详情和报文模板编辑。筛选条件写入 URL 查询参数，使刷新、前进后退和分享内部链接均能保持上下文。

会话失效时记录当前地址；重新登录后返回原页面，而不是统一回到运行总览。

## 管理员首页

首屏只展示三类可行动事项：配置不完整、消息云连接异常、最近执行失败。每项包含对象、原因、严重程度和处理入口。

首次配置或存在缺失项时，展示“消息云组件 → 数据项 → 报文模板 → 任务 → 试运行”的配置就绪度。执行趋势、成功率、投递分布和最近执行放在第二层；可交互指标应带筛选条件跳转到执行记录。

健康状态不得根据一次页面加载成功推断，也不能固定显示“运行正常”。分别展示后端接口和消息云组件状态及最近检测时间；没有真实检测结果时显示“未检测”，不能使用绿色正常状态。

## 任务操作员首页

首屏展示可历史补跑的任务、最近执行及失败结果。任务卡片展示名称、最近结果、手工执行可用性和历史补跑入口；不可补跑时说明原因。配置异常只展示对任务的影响和联系管理员提示，不展示配置编辑入口。没有任务时说明暂无可操作任务，避免引导操作员创建配置。

## 报文模板工作台

新建和编辑报文模板使用独立页面，采用左侧步骤导航、中央表单、右侧配置完整度与生成预览。步骤为基础信息、数据绑定、报文内容、投递配置、验证与发布。

保存与发布规则：

- 使用明确的“保存草稿”，显示未保存状态或最后保存时间。
- 离开未保存页面时确认；浏览器可保留临时恢复数据，但不能自动写入服务器草稿。
- 已发布版本与待发布修改分离，执行批次启动时锁定报文版本。
- 不提供版本历史、版本对比或版本恢复界面。
- 管理员可选择样例数据和业务时间生成预览，发布时再次完整校验。

发布前分开进行内容生成校验与消息云连通性检查。内容生成校验失败阻止发布；连接暂时失败允许管理员确认后发布，执行时仍须重新检查。具体阻断行为以“业务规则细化”的校验矩阵为准。

每个配置步骤持续显示“已完成、待完善、有错误”三种状态。保存草稿允许存在待完善项；发布按钮不可用时显示阻断问题数量，并能直接定位到对应步骤和字段。

预览结果应关联产生它的输入。修改报文内容、绑定、投递目标或业务时间后，原预览标为“配置已变化，请重新生成”；迟到的旧请求不能覆盖最新输入的结果。发布校验必须针对本次提交的配置。

任务和消息云组件表单同样遵守“确认保存成功后再关闭”。保存失败保留输入、定位问题并允许重试；保存成功但列表刷新失败时，提示“已保存，列表更新失败”，不能诱导用户重复创建。多位管理员编辑同一资源时，保存冲突应保留本人的输入，提示资源已被更新并提供查看最新内容的入口，不静默覆盖他人修改。

保存或发布前展示变更影响摘要，包括引用该报文模板的任务数量、自动调度中的任务数量，以及新版本从后续执行批次开始生效。修改消息云组件时同样展示受影响的报文模板和任务。

## 任务管理与执行

任务详情分别展示自动调度状态与手工执行可用性。停用只停止自动调度；存在可用的已发布报文且消息云组件有效时，任务仍可手工执行。

管理员任务详情以“立即执行”为主操作、“历史补跑”为次操作；修改配置和启停为普通操作；删除放入更多菜单的危险区。任务操作员只显示历史补跑。

历史补跑允许选择任意过去时间，禁止未来时间。确认前展示计划触发时间、业务基准时间、预报结束时间、预计数据范围、报文模板和消息云目标。历史补跑始终执行整个任务，不提供失败投递明细重试。

所有业务时间输入旁明确展示系统采用的业务时区。未来时间在字段层即时提示；确认页同时展示用户输入时间和后端计算后的业务时间，避免浏览器、服务器与业务时区混淆。

执行提交必须防止跨刷新、跨窗口的重复创建。若相同任务和业务时间已有执行批次正在处理，系统引导用户查看已有批次，而不是再次提交。

防重约束区分“同一次提交的网络重试”和“用户主动再次补跑”：同一次提交始终返回同一批次；正在处理的重复请求引导查看已有批次；原批次结束后允许用户再次手工执行同一历史时间，并生成新批次。提交超时只表示结果暂未确认，应查询是否已创建批次，不能直接显示任务执行失败。

### 调度配置与时间解释

固定间隔和 Cron 规则同时提供中文说明；保存或启用前展示由后端计算的接下来数次触发时间及业务时区。无效日期、没有后续触发时间的规则应说明原因。手工任务不展示无意义的自动调度选项。

补跑输入明确称为“计划触发时间”，在旁说明它会依据数据项规则换算为业务基准时间，避免让用户把两个时间当成同一概念。从某次执行进入历史补跑时，可预填该次计划触发时间，但必须重新计算预览，由用户确认后执行整个任务。

执行请求成功创建批次后立即进入执行批次详情，不让用户停留在持续等待的按钮上。页面持续展示当前阶段和进度。

## 业务规则细化

### R01：保存、发布与执行校验

内容预览仅生成样例，不向消息云实际投递；文件类型需要的文件读取或生成结果应单独展示。只有影响生成正确性的失败才算“内容预览失败”，连接失败单列为连接检查结果。

| 情况 | 保存草稿 | 发布 | 创建执行批次 |
| --- | --- | --- | --- |
| 名称为空或请求结构无法保存 | 阻止并定位字段 | 阻止 | 不适用 |
| 内容、绑定或目标未完善；内容生成失败 | 允许保存编辑内容 | 阻止 | 阻止 |
| 引用的资源不存在或消息云组件停用 | 允许保留草稿 | 阻止 | 阻止 |
| 内容有效，连接检查失败或不可用 | 允许 | 管理员确认警告后允许 | 预检通过前不投递，管理员与操作员均不能跳过 |
| 内容及连接检查均通过 | 允许 | 允许 | 按角色、时间与防重规则创建 |

执行预检被拒绝不应显示为投递失败；若实际执行开始后连接变化，批次记录真实失败阶段。发布检查与执行检查相互独立，发布成功不保证未来连接一直可用。

### R02：发布版本与批次快照

报文配置保存为待发布修改，发布成功后成为新的稳定版本；失败时原已发布版本保持生效。已有任务不读取待发布修改。

创建批次时固定任务标识与名称、报文版本及内容规则、数据项绑定与时间换算规则、计算后的业务时间、消息云实例标识和连接地址、发送组与 Topic。之后配置修改不改变该批次使用的配置；下次主动补跑使用届时最新的已发布版本。

数据或源文件在该批次的数据读取阶段获取，不承诺重建历史执行时的原始数据。执行证据记录实际使用的来源、生成结果及可获得的来源版本信息。凭证不得写入用户可见快照；执行所需凭证由后端受控读取，不能为新凭证暗中切换投递目标。

历史补跑表达“按指定时间重新生成和执行”，不是“原报文原样重放”。UI 应在确认摘要说明使用当前已发布配置。

### R03：时间输入与换算

部署使用后端声明的业务时区，输入与结果均展示该时区及偏移，不从浏览器时区推断。时区未获得时不提交无时区时间，显示等待配置加载。具体时区名称须在接口核对时确认。

历史补跑比较的是计划触发时间：由服务端以当前时间判断，要求严格早于服务端当前时间。业务基准时间和预报结束时间是计算结果，预报结束时间允许在未来。立即执行使用服务端当前时间作为计划触发时间，再按规则换算。

前端即时检查用于提示，最终以服务端验证为准。输入改变即令预览失效；若提交时配置版本已变化，应返回重新预览提示，不执行与确认摘要不同的计划。

### R04：重复提交与主动再执行

同一次用户确认生成请求标识；网络超时后的查询和重试沿用此标识，不因刷新生成新请求。后端必须能按标识找到原批次；标识过期或结果无法确认时明确提示，不能悄悄创建新批次。标识保留期限属于接口契约。

业务并发判定建议采用任务标识与后端计算的业务时间窗口（基准时间、结束时间或不适用）组合，而不是原始输入字符串。自动调度、立即执行和历史补跑命中同一窗口且已有批次处理中时，不创建重叠批次；手工请求返回已有批次入口，自动调度记录本次未创建的原因。不同报文版本也不绕过同一窗口的并发限制。

批次结束后，用户可再次确认同一窗口，使用新的请求标识创建新批次。超时、状态更新中断是交互状态，不等于执行失败；批次只有在后端确认后才进入成功、部分成功或失败终态。

## 关键页面规格

### P01：报文编辑页

| 区域 | 字段与默认行为 | 校验与交互 |
| --- | --- | --- |
| 基础信息 | 名称必填；描述可选；新建类型默认 JSON、编码默认 UTF-8，编辑保留原值 | 保存名称错误显示在字段下方 |
| 数据绑定 | 数据源、数据项、要素项按需选择；新建不自动选第一条 | 上游选择改变后提示受影响绑定，不能静默替换 |
| 报文内容 | 正文、生成规则；FILE 类型展示文件来源及生成配置 | 格式化、字段定位、内容预览分别有明确动作 |
| 投递配置 | 消息云组件、发送组、Topic，无静默默认目标 | 不可用资源标明原因；连接检查与生成预览分开 |
| 验证与发布 | 预览时间、生成结果、阻断问题、连接结果、影响任务数 | 输入变更使结果过期；发布时再次验证当前内容 |

页面底部固定“保存草稿”“生成预览”“发布”操作，发布为唯一主按钮；各按钮仅在相关请求处理中禁用，阻断发布不影响保存合法草稿。右侧为最近一次手动预览，不在输入时持续请求生成。

### P02：历史补跑确认

顶部显示任务名称、当前已发布报文及投递目标；输入区默认留空，提供“昨天同一时刻”快捷填入。从执行记录进入时预填原计划触发时间。日期时间按秒输入且标明时区。

“计算预览”成功后显示输入时间、业务基准时间、预报结束时间、可获得的数据范围及连接状态；未知数量标明未提供，不能显示为零。确认按钮名为“确认历史补跑”，仅在预览与当前输入匹配且预检通过时启用。提交成功进入批次详情，超时留在结果确认状态并查询原请求。

### P03：任务与执行详情

任务详情先展示调度状态和手工执行可用性，再展示配置摘要、最近结果和角色允许的动作。执行详情先展示批次结果、时间和发起人，再展示轨迹与投递明细。明细筛选只影响下方列表。找不到当前资源时保留历史摘要；没有权限访问的链接显示说明和返回入口。

## 详情与排障

任务详情和执行批次详情使用独立页面；数据项和消息云组件等较短详情继续使用弹窗。

执行批次详情按证据链组织：调度输入与业务时间 → 锁定的报文版本 → 数据读取与报文生成 → 消息云路由 → 各目标投递结果。失败时展示首次失败阶段、可理解原因和相关配置入口。技术标识、Broker 消息 ID、最终报文和文件位置作为次级诊断信息并支持复制。

失败后不提供单条重试；用户返回任务并选择对应业务时间进行历史补跑。

执行轨迹是产品的核心视觉标识，并贯穿执行前预检、运行中进度和执行结果。每个阶段展示状态、数量和耗时，失败阶段成为页面唯一的高对比焦点。

轨迹状态来自完整批次证据，不随“仅看成功/失败”的明细筛选变化。未知阶段显示“暂无阶段信息”；缺少总量时不显示推算的完成百分比；不适用的文件处理阶段不展示。部分成功应保留成功与失败目标信息，不能把整个链路一概标为完成或中断。

运行中页面定期更新并显示最后更新时间；更新失败保留最近一次结果并提示“状态更新中断”，不将其当作任务失败。批次结束或离开页面后停止进度刷新。当前接口若只返回最终结果，应先展示真实可知的“等待执行结果”，待后端提供阶段证据后再展示细粒度轨迹。

错误信息统一回答三个问题：失败发生在哪里、影响什么、下一步如何处理。数据读取失败跳转数据项，模板生成失败跳转报文模板对应步骤，路由或投递失败跳转消息云组件。

处理入口按角色调整：管理员可进入配置；任务操作员只看只读摘要、复制批次标识并联系管理员，不进入无权限页面。历史执行引用的任务或配置已经删除时，仍展示执行时的名称、目标与结果，并说明当前资源不可用。

每个执行批次记录并展示发起人、触发方式、发起时间、指定业务时间和使用的报文版本，区分自动调度、立即执行与历史补跑。

## 列表、反馈与权限

主要列表统一提供搜索、适用的状态筛选、每页条数、条件记忆和清除筛选。任务支持批量启用和停用，不支持批量删除或批量发布。执行记录继续使用后端分页。

反馈只描述用户结果，例如“任务已保存”“报文模板已删除，历史执行记录仍保留”。登录页使用“请联系系统管理员获取账号”，不暴露 PostgreSQL、Nacos 等实现细节。

加载、空结果和错误状态使用统一结构。空状态说明下一步可执行动作；错误状态保留当前筛选和输入，避免用户重试后重新填写。

### 局部加载与查询一致性

- 统计、任务、配置和执行记录分别加载与重试；统计接口失败不应阻止查看已有任务。旧数据可保留阅读，但必须标明更新时间和更新失败状态。
- 区分“尚未创建”“筛选无结果”“无权限”“读取失败”，分别提供创建、清除筛选、角色说明或重试入口。
- 快速切换关键词、状态或页码时以最后一次查询为准，不能丢弃最新条件或用旧响应覆盖新结果。错误时明确显示当前结果属于哪组条件。
- 从总览进入执行记录应携带相同时间窗口、任务和目标条件。“包含失败投递”应覆盖部分成功批次；本页统计与全量统计标明范围，不能混用。

批量启停明确标注选择范围和数量，默认仅选择当前页；提交后逐项反馈成功、失败和原因，保留失败项供管理员处理，不能用一个成功提示掩盖部分失败。

查看型弹窗默认聚焦关闭按钮；新建或编辑弹窗聚焦第一个输入项；危险确认弹窗默认聚焦取消按钮。关闭弹窗后将焦点恢复到原触发控件。

## 视觉原则

保留当前深色侧栏、浅色内容区和企业控制台基底，不照搬原型。采用中高信息密度，减少装饰性英文和技术术语；蓝色表示动作，红色仅表示失败或阻断，橙色表示警告；一个区域只保留一个主按钮。

视觉辨识度集中投入“执行轨迹”，其他页面保持克制，不继续叠加通用指标卡、渐变和装饰性图表。

窄屏必须保留系统名称、环境名称和账号帮助。长表格不能只依赖横向滚动：任务名称和状态保留在首层，技术标识、调度和最近执行折叠为次级信息，行操作收纳到菜单；执行轨迹在窄屏下改为纵向。

报文编辑页在空间不足时将预览切换为可展开区域，保留编辑位置；长表单提供固定操作栏，校验摘要可定位字段。状态同时使用文字和图标表达，键盘可完成表单与详情操作，减少动态效果偏好应得到尊重。大报文正文按需展开，明确截断范围，复制时说明复制的是完整正文还是可见片段。

## 实施顺序

优先级表示价值与依赖次序，不表示功能已完成。先核对契约，再交付依赖这些契约的交互。

| 编号 | 阶段 / 优先级 | 交付范围 | 依赖与边界 |
| --- | --- | --- | --- |
| D01 | 第一阶段 / P0 | 确认 R01–R04：权限、业务时区、发布快照、防重、预检结果结构 | 前后端共同核对；记录尚未支持的字段 |
| D02 | 第一阶段 / P0 | 角色导航、路由恢复、表单保留、局部加载、最新查询生效 | 前端可先实施，权限校验须有后端配合 |
| D03 | 第二阶段 / P0 | 发布版本、批次快照、时间换算、请求结果查询 | 依赖 D01；先完成支撑执行的后端能力 |
| D04 | 第二阶段 / P1 | P01 报文编辑、预览失效、发布校验、变更摘要、保存冲突 | 依赖 D03；不提供版本管理界面 |
| D05 | 第三阶段 / P1 | P02/P03 补跑预检、详情、审计、状态保持、调度预览 | 依赖 D03；无阶段事件时只展示等待最终结果 |
| D06 | 第四阶段 / P1 | 两种角色首页、配置就绪度、统计条件联动 | 依赖真实状态与完整查询契约 |
| D07 | 第四阶段 / P2 | 批量启停、细粒度执行轨迹、窄屏及大正文体验 | 逐项结果与阶段事件可用后交付；基础键盘与焦点随各页交付 |

## 明确不建设

- 全局多标签页。
- 消息云之外的投递渠道。
- 审批流。
- 报文版本历史、对比和恢复界面。
- 失败投递明细重试。
- 批量删除或批量发布。

## 通用验收标准

- 管理员无需外部文档即可识别配置缺失项并进入处理页面。
- 发布前可生成预览，阻断错误不能发布。
- 执行前明确展示业务时间、数据范围、报文模板和消息云目标。
- 任务操作员不能配置、发布、启停或删除，只能查看和历史补跑。
- 任务操作员看不到立即执行入口，后端也拒绝其使用当前时间执行。
- 停用自动调度后，符合条件的任务仍可历史补跑。
- 历史补跑不能选择未来时间，也不能绕过消息云异常警告。
- 所有业务时间明确显示时区，确认页展示输入时间和计算后的业务时间。
- 相同任务和业务时间不能因刷新或多窗口操作生成重复执行批次。
- 每个执行批次只使用一个锁定的报文版本。
- 执行批次展示发起人、触发方式、当前阶段、数量和耗时。
- 未执行真实检测时，界面不能显示消息云组件“运行正常”。
- 页面刷新、前进后退和重新登录后能够恢复原访问位置。
- 从详情返回后保留列表查询条件和位置。
- 错误状态说明失败位置、影响和处理入口。
- 用户提示不出现无助于完成任务的实现细节。
- 保存失败时表单不关闭、输入不丢失；保存成功后列表刷新失败不会被显示为保存失败。
- 统计接口失败时，任务等无关页面仍可使用；旧数据有明确更新时间。
- 快速改变搜索条件后，最终结果与最后一次输入一致。
- 修改配置或业务时间后，旧预览不能用于确认本次执行或发布。
- 同一次提交超时重试不会创建第二批次；批次完成后主动再次补跑同一时间仍被允许。
- 切换明细筛选不改变批次轨迹；缺少阶段数据时不虚构进度。
- 总览到执行记录的时间范围和异常口径一致，部分成功批次不会被遗漏。
- 任务操作员的错误处理入口不跳转到配置编辑页。
- 批量启停存在部分失败时，逐项展示结果与原因。
- 调度规则展示后端计算的触发时间；补跑明确区分计划触发时间与业务基准时间。

验证时至少走通管理员创建并发布、操作员历史补跑、保存失败恢复、执行结果暂未确认四个场景。记录完成时间、重复输入次数和需要解释的字段，作为后续精简交互的依据，不预设未经测量的提升比例。

### 可复现验收场景

| 编号 / 关联任务 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| A01 / D02 | 操作员登录，打开任务详情并尝试提交当前时间执行请求 | 界面只有历史补跑；后端拒绝越权模式，不创建批次 |
| A02 / D02 | 列表筛选停用任务，进入第 3 页并滚动，打开详情后返回 | 筛选、每页条数、页码和滚动位置恢复；刷新详情仍访问同一任务 |
| A03 / D02 | 填写任务后保存接口失败；另一次保存成功但列表刷新失败 | 前者保留表单与错误；后者说明已保存，不重复创建 |
| A04 / D02 | 统计接口失败，随后查看任务；搜索先输入 A 再输入 B，让 A 响应晚到 | 任务仍可查看；最终查询条件与结果均为 B |
| A05 / D03 | 操作员输入服务端未来时间；另选过去计划时间但预报结束时间在未来 | 前者拒绝；后者不因预报结束时间而拒绝；输入与结果标明业务时区 |
| A06 / D03 | 确认补跑后模拟响应丢失，刷新并使用原请求标识查询/重试 | 返回同一批次，不创建第二个；结果未知不显示为执行失败 |
| A07 / D03 | 同一任务不同计划输入换算到同一业务窗口，其中一批次正在处理；结束后再次主动补跑 | 处理中指向已有批次；结束后用新请求标识允许创建新批次 |
| A08 / D03 | 批次启动后发布新报文并修改目标；再创建下一批次 | 旧批次配置不变；下一批次采用新配置，记录各自来源 |
| A09 / D04 | 内容生成成功但连接检查失败，随后修正内容造成生成错误 | 第一种允许管理员确认后发布但不能绕过执行预检；第二种阻止发布，合法草稿可保存 |
| A10 / D04 | 预览成功后改变绑定或时间；同时另一管理员更新资源 | 旧预览失效；保存冲突保留本人输入，不静默覆盖 |
| A11 / D05 | 部分成功批次切换成功/失败明细；状态刷新中断；原任务已删除 | 轨迹不随筛选改变；提示更新中断；历史摘要仍可查看 |
| A12 / D06 | 从最近 24 小时失败指标进入记录，结果包含部分成功批次；操作员查看首页 | 时间窗口和异常范围一致；操作员有补跑和只读入口，无配置编辑入口 |
| A13 / D07 | 当前页选三项批量停用，其中一项失败；窄屏用键盘查看结果 | 展示两项成功和一项失败原因；焦点可见，动作与失败说明可访问 |

上述场景应使用真实接口或受控测试响应验证状态变化。无法提供依赖字段的功能记为未交付，不能以静态页面截图代替行为验收。

## 实施依赖与交付边界

前端可先落实表单保留、局部加载、查询一致性、状态文案、焦点和布局。后端权限校验、提交防重与结果查询、阶段进度、调度预览、发布快照、保存冲突及完整范围统计需要后端契约支持；前端能力不足时应如实展示未知或不可用，不能用模拟值替代。

D01 至少记录：业务时区与服务端当前时间来源；生成预览和连接检查的独立结果；发布及资源修订标识；批次快照字段；规范化业务窗口；请求标识查询与保留期限；批次终态和可用阶段证据；统计时间范围和部分成功口径。未确认项进入对应任务的依赖清单，不隐含为前端实现细节。

实施前逐项核对现有接口，明确字段含义、失败响应与状态来源。此方案不授权修改独立后端仓库；涉及后端协作的能力须在对应项目安排实现，并通过真实接口验证。

## 工程约束

当前前端实现与未完成项见 [实施状态](product-design-implementation.md)。目标方案与已交付能力分开记录，后端依赖未完成前不作整体验收通过。

- 后端请求继续统一通过 src/api.js，浏览器只访问相对路径 /api。
- 跨页面复用交互放入 src/components，页面编排保留在 src/views。
- 页面交互或视觉规范变化必须同步测试。
- 每阶段交付前执行 npm test 和 npm run build。
