# 报文模拟系统前端

本仓库承载报文模拟系统的 Vue 3 + Vite 前端模块。后端位于独立仓库 `pgp-ctr-msc-simulate-server`。

前端统一使用相对路径 `/api`。本地开发时，Vite 将请求代理到 `VITE_BACKEND_URL` 指定的后端 Origin，并通过 `VITE_BACKEND_CONTEXT_PATH` 补齐后端上下文路径；默认值分别为 `http://localhost:18180` 和 `/pgp-ctr-msc-simulate-server`。生产环境应由应用 Nginx 完成同等路径转换，以保持 Session 同源。

## 本地启动

需要可运行 Vite 6 的 Node.js 环境和 npm。以下命令在本 web 项目根目录执行：

```bash
npm ci
npm run dev
```

默认访问地址为 `http://127.0.0.1:5183`，开发服务监听所有网卡；端口被占用时启动失败，不会自动切换端口。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `VITE_BACKEND_URL` | `http://localhost:18180` | 后端 Origin，不包含 `/api` 或上下文路径 |
| `VITE_BACKEND_CONTEXT_PATH` | `/pgp-ctr-msc-simulate-server` | 代理时添加的后端上下文路径 |
| `VITE_DEV_PORT` | `5183` | 本地开发端口 |

这些变量由 [`vite.config.js`](vite.config.js) 从启动进程环境读取。按后端实际端口设置，例如后端监听 `8180` 时：

```bash
VITE_BACKEND_URL=http://localhost:8180 npm run dev
```

代理会把 `/api/...` 转为后端上下文路径下的 `/api/...`，并将 Session Cookie Path 重写为 `/`。

## 页面与权限

- 运行总览：展示执行统计、趋势及失败信息，支持切换统计窗口和跳转执行记录。
- 任务管理：新建和编辑任务统一使用独立配置页；任务直接配置一份或多份已发布报文。配置页使用有限宽度的数据项、数据源搜索框和每页 12 份的勾选候选列表，筛选后自动回到第一页；跨页勾选结果紧接候选列表即时形成“执行报文与顺序”，支持上移、下移和移除。任务基础字段单项最大 360px，Cron 在宽屏使用六个紧凑列，Cron 与自动执行有效期面板限制为 1080px；中窄屏自动降列。字段标签和控件值统一使用不低于 15px 的清晰字号，Cron 说明与执行顺序摘要同步放大。任务同时配置 `CONTINUE/STOP` 失败策略、调度规则和自动执行有效期。
- 报文管理：支持 JSON 报文、结构化 FILE 和非结构化 FILE、草稿、复制、数据关联、时间及系统字段绑定、多目标配置和预生成。结构化 FILE 可选择按规则生成或原报文直发；直发只保留正文与投递目标并展示 SHA-256。非结构化 FILE 按字节原样复制，仅调整文件名和外层报文引用；Shapefile 通过复选框配置同基础名文件组并预览全部目标文件。配置编辑采用分步页面，检查和绑定编辑使用抽屉。
- 文件规则模板：首屏使用与其他配置管理一致的搜索、状态筛选和分页列表；查看模板摘要后进入独立分步配置页。管理员按基本信息、三要素绑定、样例与解析、时间替换规则四步配置，规则使用结构化表单维护。模板不填写业务编码，首次保存草稿后生成 UUID 并留在配置页；发布前统一校验完整性。
- 数据项管理：只读查看数据项及要素定义。
- 消息组件管理：只管理 RocketMQ 实例、Producer Group 和 Topic；不提供云组件启停功能，列表展示最近连接检测结果。编辑器中的 Group 和 Topic 独立提供搜索、每页 8 条分页及“显示数/总数”，新增后自动定位并高亮，重复时显示高对比错误并筛选出冲突条目。JSON、结构化 FILE 和非结构化 FILE 的最终正文统一作为消息发送。
- 执行日志：分页查询执行结果，支持按报文类型、数据项、失败阶段和时间范围筛选；多报文任务按报文模板分组展示 RocketMQ 目标，非结构化 FILE 不展示二进制正文。

登录后从后端会话响应读取 `username`、`role` 和 `permissions`。`ADMIN` 可管理配置并执行当前时间或指定时间任务；`OPERATOR` 可查看业务信息、预生成报文，并按 `MANUAL_SPECIFIED` 指定时间执行和预览，不开放配置增删改、任务启停、当前时间执行及连接检查入口。实际授权由后端强制执行。

请求收到 `401` 时清除登录态并要求重新登录；`403` 展示操作错误。HTTP 请求统一通过 [`src/api.js`](src/api.js) 发出，使用同源 Session Cookie，前端不保存账号密码配置或对象存储凭据。页面读取后端会话空闲超时并在到期前 5 分钟提示；业务请求会刷新计时，不发送无条件后台心跳。

## 报文预生成与文件规则

报文选择实况或预报业务类型。JSON 等非 FILE 时间绑定继续使用“当前时间、起报时间、预报时间”；结构化 FILE 的文件名和内容时间规则同样先选择这三个一级时间来源，再选择对应的二级方式。每轮文件时间以任务计划触发时间为计算起点，立即执行和历史补跑分别使用本次执行时间和指定补跑时间。

实况报文不提供预报专用规则，也不读取或强制校验 `period`、`period_interval`、`pre_time_point`。FILE 时间规则先选择“当前时间 / 起报时间 / 预报时间”，再选择具体方式；预报时间仅在预报业务中显示，并按所选方式读取 `pre_time_point`、`period`、`period_interval`。

预生成在浏览器中检查字段替换和文件名，不发送 MQ、不保存结果、不读取实时数据，也不改写源文件；最终业务时间、生成文件及投递结果应以真实执行结果为准。

结构化 FILE 选择“原报文直发”后，页面会清理数据关联、文件规则和变量绑定，只提交 `schemaVersion: 3` 与 `processingMode: ORIGINAL_MESSAGE`。预览直接展示保存的原始正文和 UTF-8 SHA-256，不生成 Message ID、不计算业务时间，也不格式化 JSON；详情和执行明细同步展示“原报文直发”及正文哈希。该方式不会处理正文引用的文件，与 `PASSTHROUGH` 的文件复制和引用替换语义不同。

FILE 编辑器支持 `OSS`、`OBS`、`HTTP` 存储类型，填写源对象路径或 HTTP 完整 URL，源地址留空时读取外层报文 `filePath`。使用本地 Nginx 文件服务时显式选择 `HTTP`；存储连接参数由后端管理。

文件规则采用 V2 结构，上传样例后调整文件名时间绑定和内容时间绑定。文件名片段、无表头列号等在页面按“第 1 个、第 2 个”展示，保存时转换为兼容执行引擎的零基索引。当前支持：

- `PASSTHROUGH`：内容原样复制，只配置文件名时间规则。
- `DELIMITED`：表格 / 分隔文本，支持编码、分隔符及时间字段配置。
- `KEY_VALUE`：键值文本。
- `POSITIONAL_TEXT`：按行前缀、行后缀或无表头列定位时间文本。
- `FIXED_WIDTH`：读取文件头声明的字段宽度，整体平移 Year、Month、Day、Hour 组合时间并保持记录间时差。

文件规则模板页的样例上传只在浏览器读取前 512 KiB，不向后端上传，也不持久化文件正文。识别器会自动判断 UTF-8 / GB18030、文件名中的连续数字时间、分隔文本完整时间列、Year/Month/Day/Hour 等组合列、键值时间，以及带字段宽度声明的定长文件头；识别结果直接写入可编辑的 V2 规则。样例片段只作为字段定位依据，实际规则行显示识别出的字段或文件名片段；时间来源和具体方式在规则行后按两级选择展示。证据不足的普通文本会选择 `PASSTHROUGH`，避免误替换业务数据。

结构识别调用后端扫描接口；原样复制、无表头定位和定长文本不调用通用表格扫描入口，定长文件在真实执行时校验文件头。文件名不追加 SIM 或 Execution ID，同名目标允许覆盖；编辑器会显示这一行为。

管理员可在“文件规则模板”页面创建模板。模板绑定数据源编码、数据项编码和完整要素编码集合，并保存解析模式、编码、分隔符、文件名规则和内容时间规则。发布模板后，编辑结构化 FILE 按规则生成报文并依次选择数据源、数据项和要素项；页面会自动应用唯一精确匹配，并列出同数据源、同数据项的候选模板供配置人员带出完整要素集合。复制时保留报文自己的存储类型和源文件地址。已应用模板出现新版时只显示升级入口，必须由配置人员确认后才替换报文内的规则快照，不会静默升级。缺少三要素归属的内置样例已删除，未命中时引导管理员先创建并发布文件规则模板；存量报文已经保存的内联规则快照继续兼容。

非结构化 FILE 选择 `SHAPEFILE` 后，页面默认勾选 `.shp`、`.shx`、`.dbf`、`.prj`，允许按实际文件组取消附属项，但至少保留一个文件；预生成同时展示全部目标路径。真实执行时任一文件复制失败都不投递外层报文。

只有结构化 FILE 的“按规则生成”配置检查要求应用已发布文件规则模板；JSON、非结构化 FILE 和原报文直发不使用模板。仅有历史内联文件名或内容规则、但没有模板引用的结构化规则报文，草稿仍可保留数据，但不能通过配置检查或重新发布。报文复制会保留有效模板引用；修改三要素后必须重新匹配对应模板。

报文模板将 JSON 时间来源的完整语义集中展示在字段映射列表下方。文件规则模板从样例识别结果中选择“第 N 个时间：样例值”以及表头字段、无表头列、键名或定长组合字段，不显示内部零基位置、字段串或时间来源。文件模板的四步配置支持“返回上一步”和“保存并下一步”，保存成功后才进入下一步。

## 执行与防重复提交

任务执行前先获取时间预览，再确认发送。按钮通过公共动作守卫阻止并发重复提交；执行请求携带 `requestId`。

当前页面会话中，同一任务、模式和指定时间的未确认请求重试复用该标识；网络异常、`409` 或服务端错误时，前端先按 `requestId` 查询执行状态以恢复结果。该标识暂存在内存，刷新页面不会保留。后端的请求防重决定是否实际再次发送，页面按钮状态不能替代它。

## 验证与构建

2026-09-21 全局问题修正：多目标编辑保留同一 RocketMQ 实例的不同 Group/Topic 路由并按完整路由去重；原报文直发支持非 JSON 正文；复制报文清理历史时间计划和偏移；文件时间规则继续使用“当前时间、起报时间、预报时间”两级选择。前端 116 项测试和生产构建已通过。

```bash
npm test
npm run build
```

生产构建产物位于 `dist/`。

生产静态部署需要单独配置 `/api` 代理，Vite 配置不会打包进 `dist/`。`npm run preview` 用于本地预览构建产物，不作为生产部署命令。

页面使用独立地址（如 `/tasks/:id`、`/messages/:id/edit`、`/executions/:id`）。生产服务器须将非静态资源、非 `/api` 的页面路径回退到 `index.html`，否则刷新详情页会返回 404。`/api` 继续代理到后端，不可回退为 HTML。

产品方案见 [产品设计优化](docs/product-design-optimization.md)，当前实现范围、验证结果和待办见 [实施状态](docs/product-design-implementation.md)。Java 通用报文、结构化 FILE 和非结构化 FILE 的前后端统一需求见 [统一需求文档](../需求-Java通用报文文件能力.md)。后续需求变更必须先同步统一文档，再进入开发。

## 目录

- `src/`：页面、公共 UI 与接口 Adapter。
- `src/page-route.mjs`：页面地址解析与生成。
- `src/authentication.mjs`、`src/action-guard.mjs`：会话权限与异步动作防重。
- `src/file-rule-presets.mjs`、`src/file-rule-template.mjs`、`src/file-storage.mjs`：内置规则、数据库模板三要素匹配/快照和配置规范化。
- `src/message-pre-generation.mjs`：浏览器端预生成。
- `src/message-references.mjs`：统一归一化任务的单值/多值报文引用，并为删除保护、关联统计和任务回显提供同一判断。
- `src/message-content-fields.mjs`：集中解析报文正文中的时间字段、标量字段和文件引用，页面不再各自递归遍历 JSON。
- `test/`：前端行为与设计系统回归测试。
- `prototypes/`：UI 设计原型，不参与生产构建。
